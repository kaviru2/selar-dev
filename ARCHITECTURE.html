Semantic Linking for Active Retention — system design and data flow

🏗️ System Architecture

SELAR comprises four interconnected layers: a frontend console in Next.js, a Go REST API, an asynchronous Python worker for document processing, and PostgreSQL with pgvector for semantic search.

⚙️ Component Interactions

The API layer orchestrates all operations, serving as the single source of truth. The worker processes documents asynchronously and communicates results back to the database. The console queries the API for user data, documents, and suggestion status.

🔑 Key Features

  • JWT Authentication: Secure session management in selar-api
  • Async Document Processing: Worker handles CPU-intensive ingestion without blocking the API
  • Vector Embeddings: 3072-dimensional vectors stored in pgvector for semantic similarity search
  • Active Retrieval Practice: User confirms/rejects suggestions to strengthen learning through interaction
  • Knowledge Graph Extraction: Concepts and relationships extracted from documents and presented visually
  • Horizontal Scalability: Worker can be load-balanced; API is stateless; database is the single source of truth
